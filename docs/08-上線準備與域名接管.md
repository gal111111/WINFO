# 上線準備與域名接管

## 已完成的項目基礎

- 靜態 React + Vite 網站可用 `npm ci` 及 `npm run build` 建置
- GitHub Actions 會在 `main` 分支更新時建置並保留部署日誌
- 建置產物會產生 `404.html`，支援直接訪問前端路由
- `_headers` 提供基礎安全回應標頭，可由 Cloudflare Pages 套用
- `.env`、`.env.local` 及 `.dev.vars` 不會進入 Git

## 建議的部署拓撲

使用 Cloudflare Pages 託管靜態網站，HKDNR 繼續負責 `winfo.hk` 域名與 DNS

| 項目 | 設定 |
| --- | --- |
| Git repository | `gal111111/WINFO` |
| Branch | `main` |
| Build command | `npm ci && npm run build` |
| Output directory | `dist` |
| Node version | `20` |
| Production domain | `winfo.hk` 與 `www.winfo.hk` |

## 域名接管流程

1. 先確認 HKDNR 帳戶內的 Registrant、管理電郵及續費聯絡人屬於 WINFO 或獲授權人士
2. 立即更換已透過聊天工具傳送的帳戶密碼，並啟用雙重驗證
3. 匯出或截圖保留現有 DNS 記錄，特別是郵件 MX、SPF、DKIM、DMARC、Google Workspace 或 Microsoft 365 記錄
4. 在 Cloudflare Pages 建立專案並先使用預覽網域驗證網站
5. 在 Pages 加入 `winfo.hk` 和 `www.winfo.hk` 自訂網域，依頁面提示於 HKDNR 建立指定的 CNAME 或變更 nameserver
6. DNS 生效後，檢查首頁、所有服務頁、`/privacy-policy`、`/terms-of-use` 與任意不存在網址的 404 頁
7. 確認 HTTPS 憑證、`www` 導向與郵件收發均正常，才關閉舊網站

## 回滾方式

1. 在 Cloudflare Pages 選擇上一個成功部署並執行 Rollback
2. 若 DNS 已切換但新版本異常，先回滾 Pages，再視需要還原已備份的 DNS 記錄
3. GitHub Actions 的每次執行日誌可定位失敗於安裝、建置或部署階段
